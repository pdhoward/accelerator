# Demo script: the AI Cradle (Monday 2026-11-09)

About 12 minutes plus questions. Every query below was tested on 2026-11-08.

## 30 minutes before

1. **The gate is green.** app.strategicmachines.ai → Machine Shop → Policy → Conformance gate. If SCN-3 isn't retired yet, retire it, then press **Prove again**. Within a minute the card should show the version **in force** with every scenario passing.
2. **Warm up C.** Open https://machineshop-git-cradle-strategicmachines.vercel.app and run one search. The first request after a deploy takes about 7 seconds while the store compiles its rules; after that, searches take about 2 seconds.
3. **Voice (optional).** Make one short call on C with the access code. If it misbehaves, leave voice out.
4. **Open these tabs in order:**
   1. app.strategicmachines.ai/platform
   2. A, the traditional store: https://machineshop-git-baseline-strategicmachines.vercel.app
   3. C, the AI-run store: https://machineshop-git-cradle-strategicmachines.vercel.app
   4. Control Room → Machine Shop → Policy

## The talk track

**1. The problem (1 minute).** Every company's business rules are buried in code: pricing, eligibility, what the site promises. Nobody has the full list, and changing one rule takes a developer, a ticket and a release. Legacy systems, COBOL included, are the extreme case.

**2. The idea (2 minutes), on /platform.**
- Headline: *"Transform your business from running on software to running on AI. Intelligence matters."*
- Scroll to **"How a Cradle app comes to life, and how it runs"** and walk left to right:
  - your legacy app, in any language, is read, not rewritten;
  - the Accelerator turns its code into a policy book the business owns, and proves every change;
  - the new app runs in your own cloud, with your services where they are.
- **The shift:** the app boundary moves. The language model becomes the app's router and rule handler, the "operating system". Verified code (kernels) still does anything that must be exact: money, stock, checkout. The screens are built from tested components.

**3. A against C (4 minutes): the "wow".** Put A and C side by side and type the same thing into both:
- *"a cordless drill under $150 I can buy today"*: A finds **nothing**. C finds one, explains why, and shows its filters.
- *"compare brass pendant lights"*: C builds a **comparison table**.
- *"something to keep my garage floor clean"*: C understands the need and broadens its search.
- Press **Why?** on C. It shows the steps the agent took (route, ground, decide, execute, render), the time, the cost (a fraction of a cent) and **the business rules that shaped the answer**.
- In C's assistant, type *"I want to buy this drill"*. It takes you to the product page and tells you to press Buy now, exactly as the owner's ruling says. Optional: the same by voice.

**4. The rules and the evidence (3 minutes), in the Control Room.**
- **Policy:**
  - the rules in plain English, each one versioned and dated;
  - the contradictions the crew found in the old code, and the owner's rulings that settled them. For example: *"a product can be bought only when its stock status clearly says in stock."*
- **Conformance gate:** **"Each rule change ships with its evidence."**
  - Before new rules reach a customer, the app is proven against scenarios written from the rules.
  - Critical ones run three times and must pass every time.
  - Until the new rules pass, the last proven version stays in force.
- **The safest proof of the point:** the gate caught real problems this week. The assistant wasn't reliably sending buyers to Buy now; it was fixed and proven.
- **A live rule change is optional.** It takes about a minute to prove. Only do it if you've rehearsed it today.

**5. The honest numbers (1 minute), /platform → "Measured".**
- Lighthouse scores are the same for both stores.
- C answers plain-language requests that A can't.
- C costs about 1.5 seconds more and a fraction of a cent per request.
- A rule change takes about a minute, against days to weeks.

**6. Where this goes (1 minute).**
- **The app that polices itself:** like a car calling the dealer for service, it watches the regulations its rules cite and tells the owner when a change is needed, with the proposed new wording and its tests.
- **Every channel from one app:** the same answer on the web, in Slack or Teams, or by voice.
- **Less code to own:** in Machine Shop about 70% of the code is channel plumbing that the Cradle shares across apps.

## If something goes wrong

| What happens | What to do |
|---|---|
| C's first search is slow | Talk through it. "It's compiling the owner's rules", which is the point. |
| C shows the ordinary product grid instead of an answer | The agent call failed and the store fell back to classic search. Run the query again. |
| Voice doesn't connect | Skip it. The typed assistant shows the same behavior. |
| The gate card shows "held" | Show the failing case and why. That *is* the demo: rules don't go live unproven. |

## Likely questions

- **"Isn't the model unpredictable?"** That's why the gate exists. The behavior is measured, not trusted: every rule change ships with its evidence, and money, stock and checkout run in verified code.
- **"What does it cost?"** About $0.0003 per AI search (roughly $3 per 10,000). Compiling new rules costs about $0.02, and proving them about $0.20.
- **"Where does it run? Are we locked in?"** The app runs in your cloud. Next, the proven rules are baked into each deployment, so the app keeps running even if the Accelerator is down.
- **"Our systems are COBOL."** The same pipeline already reads mainframe estates. AWS's public CardDemo has been ingested in slices, read-only.
- **"Who changes the rules?"** The business owner, in plain English, in the Policy Walk. No developer.
- **"What about our data and keys?"** Secrets live in an encrypted vault, and the AI never sees them. The crew starts read-only.
